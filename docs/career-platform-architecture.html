3. Analyze resume — request flow

User uploads resume; Vercel calls Cloud Run for live analysis.

sequenceDiagram
    actor User
    participant Vercel as Vercel
    participant API as Cloud Run
    participant Claude as Claude API
    participant FC as Firecrawl
    participant GCS as Cloud Storage

    User->>Vercel: Upload resume
    Vercel->>API: POST /analyze
    API->>FC: Fetch jobs
    FC-->>API: Postings
    API->>Claude: Gap analysis
    Claude-->>API: Scores + suggestions
    API->>GCS: Store artifact
    API-->>Vercel: Results JSON
    Vercel-->>User: Charts + recommendations

7. Questions for reviewers

  • Should analysis stay on Vercel API routes or move entirely to Cloud Run?
  • Is Buildkite worth it vs GitHub Actions for Docker + Cloud Run deploy?
  • Ephemeral resume processing only, or versioned storage in GCS?
  • Nightly jobs: Buildkite schedule vs Cloud Scheduler → Run Job?
  • Highest-value surface: Analyzer, Tracker, or Market dashboard?
  • Any security concerns with Claude / Firecrawl integration?
